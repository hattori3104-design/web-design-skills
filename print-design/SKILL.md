# print-design

チラシ・フライヤー・ポスター・DMなど紙媒体のデザイン案件を、ヒアリングから入稿直前まで事故なく進めるためのスキル。
紙はWebと違い、**刷ってしまったら直せない**。このスキルの存在意義は「間違いが印刷所に渡る前に必ず捕まえる」ことにある。

---

## 最初の動き：依頼タイプで初動を変える

| 依頼タイプ | 初動 |
|---|---|
| **新規制作**（情報が不足） | 下記Step 1の要件を `ask_user_input` で最小限確認してから進める。ただし要件が揃っている、または「まずラフが欲しい」と言われたらラフ方向を先出しし、不明点は**「要確認」と明示** |
| **昨年版・前回版ベースの更新**（反復案件） | まず `references/regular-clients.md` の定番仕様と昨年版データの所在を確認。**変更点（日付・出演者・料金など）だけを差分リストにして**からデザイン検討に入る。全部を作り直さない |
| **入稿前チェックのみ**（完成データが手元にある） | 即Step 4のチェックリストに入ってよい |

---

## Step 1: 要件整理

確認する項目（反復案件は references/regular-clients.md で埋まる分を先に埋め、残りだけ聞く）：

```
1. 種類（チラシ / ポスター / DM）と用途（集客・告知・案内）
2. サイズ・向き（例: A4縦）／片面・両面
3. 部数・納期（イベント日から逆算した配布開始日も）
4. 印刷会社（入稿仕様が会社ごとに違うため）
5. 昨年版・参考デザインの有無（「昨年ベース」なら差分だけ聞く）
6. 支給素材（ロゴ・写真・出演者プロフィール等）の有無と形式
7. 予算感
```

---

## Step 2: 掲載情報チェック

紙媒体の事故の大半は「載せるべき情報の抜け・誤り」。デザインに入る前に、掲載情報を表で固定する。

| 項目 | 内容 | 状態 |
|---|---|---|
| イベント名・タイトル | | ○ / クライアント確認待ち |
| 日時（**曜日との整合を必ず計算で確認**） | | |
| 会場（正式名称・住所・アクセス） | | |
| 料金（税込表記・前売/当日・区分） | | |
| 出演者・主催・後援（**表記順や肩書はクライアント確認必須**） | | |
| 問い合わせ先（電話・メール） | | |
| QRコード・URL（**リンク先が生きているか**） | | |
| チケット取扱・申込方法 | | |

全項目が「○」か「クライアント確認待ち」になるまで埋める。空欄のままデザインに進まない。

---

## Step 3: ラフ方向の提案（2〜3案・断定しない）

デザインの最終判断はデザイナー本人がする。スキルは**方向の候補**を出す役割に徹する。

各案に含めるもの：
- **コンセプト**（誰に・何を感じさせて・どう動かすか、1〜2行）
- **レイアウト骨子**（メインビジュアルの扱い、情報の優先順位、視線の流れ）
- **配色・書体の候補**（断定せず「候補」として。反復案件は昨年版との連続性に言及）
- **写真・イラストの扱い**（支給素材で足りるか、追加が要るか）

出力の最後に必ず**「人が確認すべき箇所」チェックリスト**を付ける（コンセプトの妥当性、クライアントの好みとの整合、素材の権利関係など）。

---

## Step 4: 入稿前チェック

印刷所へ渡す前の最終関門。1項目ずつ確認して表で出力する。

| # | チェック項目 | 確認方法 |
|---|---|---|
| 1 | 誤字・脱字（特に固有名詞・出演者名） | 全テキストを一字ずつ照合（固有名詞は支給資料と突合） |
| 2 | **日付と曜日の整合**（2026年カレンダーで計算確認） | 日付→曜日を計算で照合 |
| 3 | 料金・時刻の数字（ヒアリング内容と突合） | Step 2の表と照合 |
| 4 | 塗り足し3mm（断ち切りデザインの場合） | データ設定を確認 |
| 5 | カラーモードCMYK（RGBのままだと色が変わる） | データ設定を確認 |
| 6 | フォントのアウトライン化（またはエンベッド） | 印刷会社の指定に従う |
| 7 | 画像解像度 実寸350dpi以上 | 配置画像を確認 |
| 8 | 小さい文字の黒はK100%のスミ1色（4色混合の黒は版ずれでにじむ） | データ設定を確認 |
| 9 | QRコードの動作（**実寸で試し刷りして実機読み取り**。目安2cm角以上・周囲に余白・濃色×薄背景。リンク先が本番URLかも確認） | ユーザーに確認依頼 |
| 10 | 印刷会社固有の入稿仕様（テンプレート・トンボ・ファイル形式。PDF/X-1a指定が多い） | references/regular-clients.md か印刷会社サイト |

⚠️ 6〜10はデータを直接確認できない場合が多い。その場合は「ユーザー確認事項」として明示的にリスト化し、勝手に「OK」にしない。

---

## 完了条件

- Step 2の掲載情報チェック全項目に「○」または「クライアント確認待ち」が付いている
- Step 4の入稿前チェックリストを出力し、AIが確認できない項目を「ユーザー確認事項」として明示している

---

## 反復クライアントの定番仕様

コンサート系など毎年繰り返す案件の定番（サイズ・印刷会社・毎年のお約束）は `references/regular-clients.md` に蓄積する。
**案件が終わるたびに、その案件で確定した仕様・学びを1行でも追記すること**（次回の自分への引き継ぎになる）。
