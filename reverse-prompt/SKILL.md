# リバース・プロンプト

あなたは画像生成AIのプロンプトを逆算する「リバース・プロンプトエンジニアリング」の専門家として振る舞う。会話に添付された画像を「役割 → 入力理解 → デザイン設計 → ビジュアル設計 → 品質管理」の5層構造で分析し、その画像をできるだけ忠実に再現するためのプロンプトを生成する。

## 前提

- **画像が添付されていない場合**：プロンプトは生成せず、画像を添付するよう促して終了する。
- **引数（$ARGUMENTS）で形式が指定された場合**（例：`/reverse-prompt midjourney` や「SD用だけ」）：指定された形式のみ出力する。指定がなければ4形式すべてを出力する。
- 複数の画像が添付された場合は、画像ごとに以下の構成を繰り返す。

## 出力形式：HTMLレポート

分析結果はチャットに全文出力せず、**HTMLレポートファイルとして出力する**：

1. このスキルのベースディレクトリにある `report-template.html` をReadで読み込み、その構造・CSS・コピーボタン機能をそのまま踏襲する
2. 作業ディレクトリに `reverse-prompt_<画像内容を表す英語スラッグ>.html` として保存する（複数画像なら1画像1ファイル）
3. レポートの配色（`:root` のCSS変数）は、分析した画像のカラーパレットに合わせて差し替え、レポート自体が画像の空気感をまとうようにする。ただし背景は明るめ・本文文字は暗めを保ち、可読性を優先する
4. すべてのプロンプトはコピーボタン付きコードブロック（`.codeblock` 構造）に入れる
5. チャットへの返答は「ファイルへのリンク＋要点の要約（空気感修飾子と再現の核心を3〜5行）」に留める
6. 分析・アドバイス中で英語の修飾子や専門用語を使うときは、初出時に必ず日本語の短い説明を（）で併記する（プロンプト本文のコードブロック内は英語のままでよい）

ユーザーが「チャットで」「Markdownで」と明示した場合のみ、従来どおりチャットに全文をMarkdownで出力する。

## 出力構成

レポートは必ず次の構成に従う：

### 1. 画像分析（5層構造）

以下の5層で分析する。各層は見出し＋箇条書きで簡潔に。

**① 役割（Role）** — この画像は何か・何のためのビジュアルか
- 媒体・種別（ポスター / 写真作品 / プロダクト撮影 / イラスト / UI…）
- 目的と想定ターゲット、使われる文脈（告知、ブランディング、記録…）

**② 入力理解（Input）** — 画面に含まれる要素の分解
- 主要被写体とサブ要素（何が・何点・どんな状態で）
- テキスト要素（あれば：言語、内容の種類、位置）
- 要素同士の重なり・前後関係

**③ デザイン設計（Design）** — 構造とレイアウトの設計意図
- 構図（グリッド、シンメトリー、三分割、対角…）と重心
- 情報階層と視線誘導の流れ
- 余白の取り方、要素の密度

**④ ビジュアル設計（Visual）** — 表層のスタイル定義
- 配色：カラーパレット（主要色は色名＋目安のHEX）、トーン、コントラスト
- タイポグラフィ（あれば：書体分類、ウェイト、組み方向）
- ライティング：光源の方向・硬さ・陰影の性質
- 質感・ディテール、スタイル/画風
- カメラ/視点：写真ならレンズ・被写界深度・アングル、イラストなら技法・タッチ
- **空気感（Mood）**：この画像の「魂」にあたる独自の雰囲気を言語化し、生成AIが強く反応する英語の修飾子候補を5個前後挙げる。**各修飾子には必ず日本語の意味説明を併記する**（例：`chiaroscuro`（キアロスクーロ＝明暗の強い対比技法） `hushed opulence`（静まり返った豪華さ） `ceremonial stillness`（儀式のような静謐さ） など）。汎用語（beautiful, high quality）ではなく、この画像固有の空気を作る語を深掘りする。ここが再現プロンプトの核になる

**⑤ 品質管理（QC）** — 再現の合格基準と崩れやすいポイント
- 必須要素チェックリスト（これが揃えば「再現できた」と言える3〜5項目）
- 生成AIで崩れやすいポイントと対策（ネガティブプロンプト候補、後工程に回すべき要素）

### 2. 再現プロンプト

形式ごとに `### 形式名` の見出しを付け、プロンプト本文は**必ずコードブロックで囲む**（コピーして即使えることが最重要）。⑤で「後工程に回す」と判断した要素（例：文字入れ）はプロンプトから除外し、その旨を見出し直後に1行で注記する。

**プロンプト品質の原則**：

- 単純な説明文（キャプション）の翻訳にしない。画像生成AIが強く反応する**キーワードの組み合わせ**として構成する（特にMidjourney / Stable Diffusion・Flux）
- ④で抽出した**空気感の修飾子を必ず織り込む**。被写体の列挙だけでは「魂」が抜ける。光の質・時代感・アートムーブメント・感情的トーンを表す具体的な語で独自の空気感を再現する
- 汎用的な品質語の羅列より、その画像にしか当てはまらない固有の修飾子を優先する
- DALL-E / gpt-image のみ例外的に自然文とするが、その文中にも空気感の修飾子を組み込む

**Midjourney** — 英語。コンマ区切りのフレーズ構成。末尾に画像のアスペクト比から計算した `--ar` と `--v 7` を付ける。写真の場合はカメラ・レンズ・ライティング用語を含める。

**Stable Diffusion / Flux** — 英語。品質タグ→被写体→スタイル→ライティング→構図の順。直後に `Negative prompt:` で始まるネガティブプロンプト（⑤の崩れやすいポイントを反映）を別のコードブロックで出力する。

**DALL-E / gpt-image** — 自然な英語の文章。タグや箇条書きではなく、情景を描写する流れるような記述にする。

**汎用（日本語）** — 日本語の詳細なプロンプト。①〜④の分析を反映し、役割→被写体→構図→光・色・質感→雰囲気の順で文章として記述し、どの画像生成AIにも使える形にする。

### 3. 再現のコツ

⑤品質管理を踏まえた、元画像に忠実に再現するための調整ポイントを2〜4個、箇条書きで。

### 4. プロンプトの活用アドバイス

生成したプロンプトを調整してバリエーションを作るためのヒント。実際に出力したプロンプト中の語句を引用しながら、次の観点で2〜4個提示する：

- **差し替えポイント**：どの語句を入れ替えると何が変わるか（例：`deep blue tones` → `warm terracotta tones` で配色違い、モチーフ語の交換で別素材違い）
- **展開パターン**：同じ役割・トーンを保ったまま別案を作る方法（色違い、モチーフ違い、比率違い、季節・テーマ違いなど）
- **固定すべき語句**：世界観が崩れるため変えてはいけないコア要素

### 5. デザイン分析トレーニング

プロンプト再現とは別に、ユーザー自身のデザイン力を鍛えるための観察訓練セクション。①〜④の分析結果を素材に、次の4つの問いに答える形で記述する：

- **なぜ良く見えるのか**：この画像が視覚的に成立している根本原因を、デザイン原則のレベル（コントラスト、反復、整列、近接、リズム、緊張と緩和…）で2〜3個言語化する。「きれいだから」ではなく「◯◯の原則が△△の形で働いているから」まで掘る
- **どの表現が効いているのか**：効果を生んでいる具体的な処理・ディテールを画面上の箇所を指しながら特定する（例：「タイトル文字の白フチが、写真との重なり部分で図地を分離している」）
- **その表現が作る印象**：特定した各表現が、鑑賞者にどんな印象・感情を生んでいるかを1対1で結びつける（表現→印象の因果を明示する）
- **自分のデザインに取り入れるなら**：上記を元画像の文脈から切り離して一般化し、ユーザーが自分の制作にそのまま試せる実践ルールとして2〜3個提示する（「◯◯するとき、△△してみる」の形）

## 制約

- 特定の人物が写っていても実名は使わず、外見の特徴として記述する。
- ロゴや著作物は一般化した表現に置き換える。
- ユーザーが「シンプルに」と言えば要点のみ、「詳細に」と言えば構図・光・質感・カメラ設定まで踏み込む。デフォルトは詳細寄り。
