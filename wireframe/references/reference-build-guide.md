# 参考サイトを使った実装（モードC）ガイド

ワイヤー・デザイン方向性が固まったあと、「実際に動くアニメーション付きのサイト」を
Claude Codeでそのまま作りたいときの進め方。Figma Makeプロンプト（モードB）とは違い、
コードとして動くサイトを直接作る場合に使う。

すでに導入済みの frontend-design スキルと組み合わせて使う。新しく何かをインストールする必要はない。

**注意**：外部の「〇〇スキルをnpmでインストールして」系の手順は、たとえ効果がありそうでも使わない
（安全ゲート：外部スキルはそのままコピーしない）。ここに書くのはインストール不要の「進め方」だけ。

---

## 進め方

### 1. 参考サイトをセクションごとに集める

理想のサイトを言葉だけで説明しようとせず、実物を見せる。

- 参考サイト（Awwwardsやクライアントが提示したサイトなど）を、ページ全体ではなく**セクションごとに**スクリーンショットする
  例：ヒーロー／作品一覧／個別ページ／フッター／ローディング画面
- 1つのサイトに理想の形が全部揃っていないことが多い。ヒーローはA社、一覧の見せ方はB社、のように**良いところだけを複数サイトから借りてよい**
- 集めた画像はプロジェクト内の `reference` フォルダにまとめて入れる

### 2. 作業前に「質問して」と一言添える

指示の最後に必ずこの一文を入れる。

> 作り始める前に、確認したいことがあれば質問してください。

この一言があると、Claudeはスタイル・フォント・セクション構成・アニメーションの度合いなど
4〜6個の質問を返してくる。ここで具体的に答えるほど、後の手直しが減る。

### 3. まとめて一気に修正依頼する

サイトができたら、自分でスクロールして気になった点をすべて書き出す。
1つずつ送らず、**リストにしてまとめて1回で**送る。

```
直してほしい箇所がいくつかあります。すべて対応してください。
1. [問題1]
2. [問題2]
3. [問題3]
```

### 4. 仕上げに6項目で自己点検させる

最後に、Claude自身に以下の観点で点検・指摘させる。

```
次の観点でこのサイトを評価し、改善が必要な点は正直に指摘してください。
- タイポグラフィ（使い古されたAIフォントを使っていないか）
- カラー（配色は抑制が効いているか、それとも散漫か）
- 階層（文字サイズが視線を正しく誘導しているか）
- アニメーション（滑らかで意図的か、それともぎこちなく脈絡がないか）
- モバイル（本当にスマホ向けに設計されているか、単に縮小しただけではないか）
- 文章（抑制が効いて具体的か、それともAIにありがちな中身のない文章か）
```

指摘された内容をすべて採用する必要はない。自分の直感で「これは違う」と思えば見送ってよい。

---

## 提案書・単価との結びつけ方

この進め方で作った「動くアニメーション付きサイト」は、口頭やワイヤーだけでは伝わらない
高級感・こだわりを見せる材料になる。提案時に「静止画の提案書」に加えて、簡易でも
動く試作を見せられると説得力が上がる。pre-submit-checkのc10（成果・数字）・c11（金額の根拠）
とあわせて、「作れる質の高さ」を見せる材料として使う。
